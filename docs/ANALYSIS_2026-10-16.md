## 1. Кратко

Notepad Hub 4 (NH4) — локальный Windows-редактор заметок: WPF-хост + WebView2 + React/TypeScript (редактор BlockNote) поверх .NET 8-ядра, с файловой моделью данных, совместимой с NH3, и AI-помощником с жёсткой моделью согласий и бюджетов.

Проект **заметно выше среднего по культуре безопасности и надёжности записи**: атомарные writes, SSRF-защита загрузки изображений, DPAPI, сканер секретов перед отправкой в облако, потолки стоимости, single-instance mutex, бэкапы с манифестом и rollback. При этом есть реальные дефекты и пробелы инфраструктуры: **не работал ни один из 11 UI-тестовых файлов** (сломанные импорты), не было **CI**, dev-сервер Vite проксировал AI-запросы **без согласий и лимитов хоста**, облачный AI-запрос **не отменялся** при закрытии диалога подтверждения, смешанные окончания строк **приводились к CRLF** при write-through, импорт файлов через drag-and-drop читал всё как UTF-8, не было **печати**, а установщик не предлагал даже опциональной интеграции с `.txt`.

В рамках этой работы **все перечисленные дефекты исправлены и покрыты тестами** (см. раздел 6): UI-тесты — 146/146 (было 30/41 при 11 неработающих файлах), Core-тесты на Linux — 172/190 (все 18 «падений» — платформенные артефакты DPAPI/путей, идентичны базовой линии; в Windows CI они проходят), добавлены `NetworkGuardTests` (5/5) и `LineEndingsTests` (5/5), создан GitHub Actions CI. Структурные проблемы (god-компонент `App.tsx`, загрузка всей библиотеки в память, отсутствие синхронизации/E2EE, бандл 1,5 МБ) задокументированы с рекомендациями, но не правились — их изменение без Windows-окружения и E2E-воспроизведения было бы слепым и рискованным.

## 3. Архитектура и сильные стороны

Схема: **WPF-хост** (окно, WebView2, мост C#↔JS, DI ключей/согласий) → **React/TS UI** (BlockNote-редактор, шорткаты, wiki-ссылки) → **NotepadHub.Core** (файловое хранилище, AI, совместимость, бэкапы). Данные — обычные файлы в `%LOCALAPPDATA%\NotepadHub\data-v3`, совместимые с NH3.

Что сделано хорошо (проверено чтением кода, не по документации):

1. **Надёжность записи.** Атомарная запись (temp → flush → `File.Replace`), `SafeId`-защита от path traversal, писательский замок и сосуществование с NH3.
2. **SSRF-защита `ImageFetcher`.** Разрешение DNS прямо в `ConnectCallback` (защита от DNS-rebinding), блокировка частных диапазонов и NAT64, ≤3 редиректов, лимит 10 МБ, sniffing по magic bytes без поддержки SVG.
3. **Модель согласий AI.** Все облачные вызовы — только через хост с явным подтверждением; `SecretScanner` (14 правил) перед отправкой; потолки $0,25/запрос и $5/месяц; rate-limit 10/мин и 100/день; Ollama — только loopback, псевдопровайдер `:cloud` заблокирован.
4. **Валидация compat-провайдеров.** `CompatServiceStore.Validate`: только https, http — лишь loopback.
5. **Write-through к внешним файлам.** Блоки с SHA-256, детекция конфликтов (±2 с), сохранение исходной кодировки, бэкап перед перезаписью.
6. **Прочее.** Single-instance mutex + pipe; hardening WebView2 и CSP; бэкапы `.nhub` с манифестом и rollback; защита промптов от инъекций (`AiPrompts`); идемпотентные upsert-ы `HostSync`; автоочистка корзины (30 дней).

По совокупности это уровень, сопоставимый с хорошими open-source проектами категории privacy-first (SiYuan, Joplin), и выше большинства «Notion-клонов».

### 4.3. Структурные проблемы (задокументированы, не правились — см. раздел 7)

- **W-13. God-компонент.** `ui/src/App.tsx` — 2 368 строк: состояние, шорткаты, drop, AI-панель, модалки, write-through — всё в одном компоненте. Любая правка рискованна, тестирование возможно только через `loadTs`-хаки.
- **W-14. Масштабирование.** При старте вся библиотека загружается в память (заметки + контент). Obsidian держит vault-ы 50k+ заметок за счёт кэшированного графа ссылок и ленивой загрузки; NH4 упрётся в память и время бутстрапа на нескольких тысячах заметок.
- **W-15. `UseProxy=false` по умолчанию.** `HttpClient` с `UseProxy=false` ломает удалённый AI у пользователей за корпоративным прокси (типичный сценарий для Windows-приложения). Обойти можно, только правя конфиг вручную; настройки прокси в UI нет.
- **W-16. Бандл 1,53 МБ** (index) + 433 КБ (native) + 427 КБ CSS, без code-splitting (`manualChunks`/динамические импорты). Для локального приложения не критично, но Vite сам предупреждает при сборке.
- **W-17. AI-конфигурация дублируется в трёх местах** (ядро, хост, dev-guard) — промпты и лимиты придётся синхронизировать вручную.
- **W-18. Нет линтеров/форматтеров** (eslint, prettier, `dotnet format`) и **нет LICENSE** — юридически проект «all rights reserved», форкать/использовать нельзя.
- **W-19. Мелочи UX/данных:** wiki-ссылки резолвятся по заголовку (переименование дублей заголовков ломает ссылки); история версий — максимум 50 копий без стратегии прореживания; подтверждения через `window.confirm`; E2E-набор невоспроизводим (нужны Windows + профиль-zip + Playwright, в репозитории не запускается).
- **W-20. D-20 (известный, не исправлен):** перезагрузка библиотеки может потерять правки за доли секунды — гонка debounce-сохранения и reload. Требует воспроизведения на Windows; слепая правка опаснее документирования.
- **W-21. Pollinations как дефолтный AI-провайдер без ключа** — приватность заметок по умолчанию зависит от стороннего бесплатного сервиса; стоит явное предупреждение в UI при первом включении.

## 6. Внесённые улучшения (полный список)

Все правки — в ветке `improvements/2026-10-16` на базе `fb53931`.

### 6.1. Тестовая инфраструктура UI (W-01)

- Новый `ui/tests/helpers/loadTs.mjs` — загрузка `.ts/.tsx` через esbuild-трансформацию для `node --test` (без Jest/Vitest, по образцу существующих qa2-тестов).
- 11 тестовых файлов переписаны на этот паттерн: `aiAnalysis`, `aiMarkdown`, `aiStructure`, `autoFormat`, `compareNotes`, `imageEdit`, `noteMeta`, `pasteImages`, `promptLibrary`, `textFormat`, `transformations` (+ обновлены `shortcuts`, `wikiLinks`).
- `ui/package.json`: `test` → `node --test tests/` (работает и в Windows-cmd), добавлен devDep `esbuild`.
- Найден и исправлен **настоящий дефект** при починке тестов: QA2-L3, wiki-ссылки в ячейках таблиц (W-06).

### 6.2. Guard dev-сервера AI (W-02)

- Новый `ui/dev/aiDevGuard.ts` + middleware в `ui/vite.config.ts`: прокси к Ollama доступен только с токеном, который dev-страница получает после явного «согласия» (эмуляция хостового consent); без токена — 403. Тесты `ui/tests/devGuard.test.mjs` (6/6), фактическая проверка curl (200/403/403).

### 6.3. SSRF-защита AI-трафика (W-03)

- Новый `src/NotepadHub.Core/Net/NetworkGuard.cs`: проверка целевого IP перед соединением (частные/loopback-нарушения/NAT64/link-local), используется как `ConnectCallback`-делегат.
- `ImageFetcher` переведён на делегат guard-а (без изменения поведения своих проверок).
- `AiService`: во всех 6 сетевых точках маршрутизация `cfg.Local ? _http : Remote`; retry-логика вынесена в статический `SendWithRetryAsync`; `MainWindow.xaml.cs` передаёт защищённый удалённый клиент в оба места создания `AiService`.
- Тесты `tests/NotepadHub.Core.Tests/NetworkGuardTests.cs` — 5/5 (keyless-варианты, т.к. DPAPI на Linux недоступен).

### 6.4. Окончания строк при write-through (W-04 / N-06 / Q2_03)

- `NoteStore.MergeLineEndings` (public static): контент с `\r`, но без `\r\n` → без изменений; оригинал без CRLF → без изменений; иначе построчно: неизменённые строки сохраняют своё окончание, изменённые/новые получают доминирующее (большинство, при равенстве — CRLF), последняя строка окончания не имеет. Семантика чистой CRLF-библиотеки побитово совпадает со старым поведением.
- Тесты `tests/NotepadHub.Core.Tests/LineEndingsTests.cs` — 5/5: сценарий Q2_03 (`"a\r\nb\nc"` + `"a\nb\nc!"` → `"a\r\nb\nc!"`), CRLF-паритет, доминирующее окончание для добавленных строк, passthrough-случаи, отсутствие «лишнего» trailing newline.

### 6.5. Отмена облачного AI-запроса (W-05 / Q2_07)

- `AiService.OpenRouterRequestAsync` и `AiService.CompatRequestAsync`: `ct.ThrowIfCancellationRequested()` сразу после диалога подтверждения, до `CommitCloudCall`/`ReserveSpend` — отменённый запрос не списывает бюджет и квоту (возврат не нужен: списания ещё не было).
- Проверка: фильтр QA2 `Q2_06|Q2_07|Q2_08` — 3/3 на Linux (Q2_07 падал до правки).

### 6.6. Импорт файлов: кодировки и бинарники (W-07)

- Новый `ui/src/decodeText.ts` — точное зеркало серверных `LooksBinary`/`DecodeText`: NUL в первых 8 КБ или >1% управляющих байтов → бинарник (импорт отклоняется); BOM UTF-8 / UTF-16LE / UTF-16BE; strict UTF-8; fallback windows-1251; затем lossy UTF-8.
- `App.tsx#importTextFile`: `file.text()` заменён на `arrayBuffer()` + `looksBinary` + `decodeTextBytes`.
- Тесты `ui/tests/decodeText.test.mjs` — 5/5 (включая cp1251 «Привет» = `CF F0 E8 E2 E5 F2`, BOM-ы, бинарный отказ, отсутствие исключений).

### 6.7. Уникальность id заметок (W-08)

- `createNote`: `note-${Date.now()}-${Math.random().toString(36).slice(2,8)}`.

### 6.8. Печать (W-10)

## 7. Что сознательно НЕ делалось и рекомендуемая дорожная карта

Без Windows-окружения, E2E-профиля и возможности ручного прогона WPF-хоста следующие правки были бы слепыми. Рекомендуемый порядок (по соотношению польза/риск):

1. **LICENSE** (W-18) — добавить AGPL-3.0 или MIT. Час работы, снимает юридический блок.
2. **Прокси** (W-15) — настройка `UseProxy`/`ProxyUrl` для удалённого AI в UI (сейчас `UseProxy=false` молча ломает корпоративные сети).
3. **D-20** (W-20) — воспроизвести гонку перезагрузки на Windows, затем чинить (вероятное решение: await незавершённого debounce-сохранения перед reload, либо версионирование последнего сохранения).
4. **Декомпозиция `App.tsx`** (W-13) — вынести drop/import, AI-панель, модалки, write-through-логику в хуки/модули; делать только после восстановления E2E.
5. **Ленивый бутстрап** (W-14) — подгружать контент заметок по требованию, в памяти держать метаданные (ориентир: Obsidian/SiYuan).
6. **Code-splitting** (W-16) — `manualChunks` для BlockNote/AI-панели; предупреждение Vite уйдёт.
7. **Единый источник AI-конфигов** (W-17) — промпты/лимиты в одном модуле, dev-guard и хост читают его.
8. **Линтеры** (W-18) — eslint+prettier для `ui/`, `dotnet format` для C#, шагом в CI.
9. **Предупреждение о Pollinations** (W-21) — явный баннер при первом включении дефолтного keyless-провайдера.
10. **Стратегия синхронизации** — если проект метит в категорию Joplin/SiYuan: WebDAV-синхронизация + E2EE (опционально, как у Joplin) — крупнейший продуктовый пробел (раздел 5).
11. **История версий** (W-19) — прореживание 50 копий (например, экспоненциальное: N последних, затем N/день, N/неделя).
