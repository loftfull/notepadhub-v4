Это другой класс продукта — исследовательский «блокнот-ассистент» (аналог NotebookLM): источники (PDF, видео, веб), чат с цитатами, трансформации, подкасты, 20+ провайдеров моделей. ## Сравнение

| Область | Open Notebook | Notepad Hub 4 | Вывод |
|---|---|---|---|
| Хранение | SurrealDB в Docker, сервис всегда запущен | Файл на заметку (`.txt` + JSON), без сервера | У нас проще и надёжнее для блокнота; сохраняем |
| Установка | Docker Compose, две службы | Один exe, ставится рядом с 3.0.5 | Наше преимущество |
| Сеть по умолчанию | UI и API слушают все интерфейсы, пароля нет (сами рекомендуют закрывать) | Только loopback, ключ в DPAPI, согласие на облако, лимиты и потолок стоимости | Наше преимущество |
| Выбор контекста для AI | Пользователь выбирает, что именно отдать модели (по источникам, 3 уровня) | Выделение / абзац / вся заметка + предпросмотр отправляемого | Есть основа, нет контекста из нескольких заметок |
| Ответы с источниками | Чат с цитатами на источники и заметки | Анализ заметки с цитатами; чата нет (по плану продукта — не нужен) | Паритет для нашей задачи |
| Трансформации | Встроенные и свои | Быстрые действия + свои рецепты + правила письма | Паритет |
| Поиск | Полнотекстовый + векторный | Был: линейный перебор всех заметок при каждом рендере, без ранжирования | **Слабое место, исправлено** |
| Связи между заметками | Через источники/инсайты | Не было | **Слабое место, добавлено `[[ссылки]]` + обратные ссылки** |
| Ключи провайдеров | Хранятся в БД, шифруются секретом | DPAPI, не возвращаются странице | Лучше |
| Подкасты, видео/аудио-источники | Есть | Нет | Вне назначения блокнота, не берём |
| Векторный поиск | Есть | Нет | Не берём сейчас: нужны эмбеддинги и фоновый индекс; для сотен заметок хватает ранжированного поиска |

## Слабые места Notepad Hub 4, найденные при аудите

1. **Поиск считался на каждый рендер** по всем заметкам, даже при закрытом окне поиска. С тысячами заметок это тормозило бы набор текста. Исправлено: поиск работает только пока открыт, текст заметок кэшируется по массиву блоков, пересчитывается только изменённая заметка. Результаты ранжируются (название > метка > текст, все слова должны совпасть) и показывают фрагмент.
2. **Нет связей между заметками.** Заметки были изолированными файлами. Добавлено: `[[название]]` (и `[[название|подпись]]`), подсветка в тексте, переход по Ctrl+клик, вставка по Ctrl+L, панель «Связи» под листом (обратные и исходящие ссылки, создание заметки по несуществующей ссылке). Ссылки — обычный текст в `.txt`, формат хранения не менялся, 3.0.5 читает такие заметки без потерь.
3. **`App.tsx` — монолит (~90 КБ).** Логика заметок, AI, поиска, диалогов и разметки в одном компоненте. Риск: каждая правка трогает всё. Частично вынесено в модули (`wikiLinks`, `searchNotes`, `FindBar`, `AiAssistantPanel`); дальнейшее разбиение — отдельный рефакторинг с тестами.
4. **Все заметки загружаются в память при старте.** Для 58 заметок это мгновенно; для тысяч нужна ленивая загрузка по запросу хоста. Не сделано, записано в план.
5. **AI-контекст ограничен одной заметкой.** У Open Notebook пользователь собирает контекст из нескольких источников. Для нас естественный вариант — «заметка + связанные заметки» с обязательным предпросмотром и проверкой секретов. Не сделано: область (`scope`) проверяется хостом и привязана к логике «Применить», изменение затрагивает контракт моста и безопасность. Нужно отдельное решение владельца.
6. **Переименование не обновляет ссылки.** Название берётся из первого заголовка и меняется при правке, поэтому автозамена `[[старое]]` в других заметках была бы небезопасной. Сломанная ссылка показывается пунктиром, клик создаёт заметку. Нужно решение: связывать по неизменяемому идентификатору.
7. **Не закрыто с прошлых проверок:** месячный бюджет и сохранение дневного счётчика AI, подтверждение платного запроса на стороне хоста, `npm audit`, проверка Origin у dev-маршрута Vite.

## Что перенесено

- Принцип «пользователь видит и контролирует, что уходит модели» — уже был, усилен в новой панели AI (плашка «остаётся на компьютере / уйдёт в облако», предпросмотр, согласие).
- Ранжированный поиск с фрагментами.
- Связи между заметками и обратные ссылки.

## Что сознательно не берём

Docker/БД-сервер, подкасты, мультимедиа-источники, векторный поиск, чат — они противоречат назначению (лёгкая замена Блокнота) и плану `PRODUCT_PLAN_MINIMAL`.
