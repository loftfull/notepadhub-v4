# Аудит зависимостей и масштаба (2026-10-10)

## Уязвимости
- **npm, runtime (`npm audit --omit=dev`)**: 0 уязвимостей.
- **npm, все пакеты (`npm audit`)**: 1 замечание уровня high — `vite <= 6.4.2` (сервер разработки). В приложение не попадает: Vite только собирает `ui/dist`; dev-сервер слушает локальный адрес и нужен только для `npm run dev`. Обновление до Vite 7 — мажорное, делать отдельной задачей с прогоном всех проверок. Принятый риск до тех пор.
- **NuGet**: `NotepadHub.Core` и `NotepadHub.Host` — без уязвимых пакетов. В тестовом проекте транзитивно `System.Net.Http 4.3.0` и `System.Text.RegularExpressions 4.3.0` (high) из тестового SDK; в поставку не входят.

## Масштаб: библиотека из 3000 заметок (~3 КБ каждая), `ScaleTests`
| Что | Время / размер |
|---|---|
| Открытие хранилища (`Initialize`) | ~0,3 с |
| `bootstrap` на стороне хоста | ~0,7 с |
| Размер ответа `bootstrap` | ~43 МиБ JSON |

Вывод: хост справляется, узкое место — размер одного сообщения моста и разбор/хранение всего текста в странице (блоки, индекс ссылок, поиск). Для десятков и сотен заметок это незаметно; около тысячи начнёт ощущаться, к трём тысячам — заметно. Тест `ScaleTests` ловит десятикратную деградацию на стороне хоста. Следующий шаг (отдельная работа): `bootstrap` без текста для неоткрытых заметок, подгрузка по `openNote`, поиск и индекс ссылок в хосте.
