## 3. Дефекты

Формат: severity, как воспроизвести, доказательство, исправление. Доказательства-тесты: `tests\NotepadHub.Core.QA\Defects.QA.cs` (запуск `dotnet test tests\NotepadHub.Core.QA`).

### Критично

**D-01. Открытие файла «на месте» затирает настоящий файл, если для него уже есть заметка из переноса Блокнота Windows**
- Причина: `NoteStore.ImportFile` (`NoteStore.cs:609-610`) находит старую заметку с тем же `SourcePath` и возвращает её, не перечитывая диск. `OpenInPlace` (`:697-702`) включает write-through для неё. У таких заметок `SourceLastWriteUtc` пуст, а `SaveToSource` проверяет внешнюю правку только при разборе этого поля (`:643-645`). Проверки нет, файл перезаписывается.
- Это реальные данные: в `data-v3.zip` у **26 из 26** файловых заметок `SourceLastWriteUtc` пуст; e2e сообщает 15 заметок «empty-with-file» (текст в файле, в заметке пусто).
- Воспроизведение: перенести снимок Блокнота Windows, где вкладка была файлом; «Файлы и данные → Открыть файлы…», выбрать этот файл; в пустой заметке набрать один символ. Файл на диске становится этим символом. Событие `conflict` не приходит. Копия прежнего файла остаётся в `backups-v3\source_*` (единственная защита).
- Доказательство: `QA01` падает: «Файл затёрт одним символом без конфликта. Содержимое файла теперь: 'x', события: saved». `QA02` (непустая, но устаревшая заметка): «Новый текст файла потерян без конфликта… Файл: 'старый снимок из Блокнота + правка'».
- Исправление: в `ImportFile`/`OpenInPlace` для найденной существующей заметки сравнивать текст заметки с диском; при расхождении или пустом `SourceLastWriteUtc` брать диск (как делает `ResolveSourceConflict("disk")`, с записью старого текста в историю) либо сразу показывать конфликт. В `SaveToSource` пустой `SourceLastWriteUtc` при существующем файле считать конфликтом (кроме создания нового файла). Закрепить тестом из QA01/QA02 в основном наборе.

### Важно

**D-02. Конфликт не обнаруживается, если `SourceLastWriteUtc` пуст (общая причина D-01)** — см. выше; затрагивает и обычное сохранение `SaveToSource(id)`, а не только write-through.

**D-03. `ResolveSourceConflict` и `SaveToSource` не повторяют проверки, которые есть в `SetWriteThrough`** (безопасность, защита в глубину)
- `SetWriteThrough` требует локальный диск и текстовое расширение (`:687`). `ResolveSourceConflict("mine")` вызывает `SaveToSource` для любой заметки с `SourcePath` без этих проверок, а при `SourceType="local"` не срабатывает и `IsExternalOnly`. `ResolveSourceConflict("disk")` читает любой `SourcePath` (в том числе `.env`) и копирует текст в `notes-content` и историю.
- Мост страницы путь не принимает (это хорошо: `openFiles` идёт через родной диалог, `setWriteThrough`/`resolveSourceConflict` принимают только id). Но `.nhub` при восстановлении не очищает `SourcePath`/`SourceType` (`NhubBackup.Inspect` проверяет только `Id`), а `WriteThroughIds` переживает восстановление и удаление заметки (D-19). Источник риска: чужая или подделанная `.nhub` плюс вызов моста.
- Доказательство: `QA03` («echo pwned» записан в `startup.bat`), `QA04` («ResolveSourceConflict(disk) скопировал .env в хранилище»).
- Исправление: вынести проверку «разрешённый источник» (локальный диск, не UNC, расширение из белого списка, `SourceType=="file"`) в одну функцию и вызывать из `SaveToSource`, `ResolveSourceConflict`, `WriteThrough`; при восстановлении `.nhub` сбрасывать `SourcePath` у заметок и сверять `WriteThroughIds` со списком заметок. Симлинки и junction не проверяются нигде (`File.Replace` по ссылке) — добавить `FileAttributes.ReparsePoint` в проверку.

**D-04. Кодировка и переводы строк исходного файла сохраняются не полностью**
- Файл в Windows-1251 читается верно (запасной вариант `DecodeText`), но записывается обратно как UTF-8 без BOM: `SaveToSource` знает только BOM-кодировки (`:665-668`). Для кириллицы это типичный случай старых `.txt`. UTF-16 с CRLF теряет CRLF: признак ищется в `Encoding.UTF8.GetString` байтов UTF-16 (`:651`).
- Доказательство: `QA05` (прочитано/записано как `РїСЂРёРІРµС‚…`), `QA06` («Expected: a\r\nb!, Actual: a\nb!»).
- Исправление: запоминать кодировку при чтении (`DecodeText` возвращает кодировку), писать в ней; признак CRLF определять после декодирования.

**D-05. Согласия на отправку в облако и подтверждение цены — только флаги, которые присылает страница**
- `remoteConsent` и `costConfirmed` — поля запроса (`AiService.cs:225,247`). Интерфейс всегда шлёт `costConfirmed: true` (`App.tsx:765`) и опирается на `window.confirm`. Подмена страницы (XSS в разметке заметки, расширение) обходит оба барьера; хост подтверждения у пользователя не спрашивает (в отличие от `ConfirmRestore`).
- Смягчение: суточный лимит 100, минутный 10, потолок $0,25 за запрос, месячный бюджет, сканер секретов, CSP. Это выдерживает случайность, но не злонамеренную страницу.
- Исправление (если угроза учитывается): родной диалог хоста для первой отправки в облако и для платных запросов; не принимать согласие от страницы.

**D-06. Контекст «+ связанные»: накладные расходы разметки не входят в бюджет**
- `buildLinkedEntries` вычитает из бюджета 22 000 только длину текста (`App.tsx:286-287`), а к каждому блоку добавляются `[B12] `, `«Название»: ` и `\n\n` (около 25-140 знаков). Заметка с сотнями коротких строк даёт больше 24 000, хост отвечает 400 «Проверьте задачу…» (`AiService.cs:235`), пользователь не понимает причины.
- Расчёт, не проверено в окне: 5 заметок по 3 000 знаков в блоках по 20 знаков = 750 блоков × ~40 знаков разметки ≈ 30 000 знаков сверху.
- Исправление: считать бюджет по готовой строке (`[Bn] …`), а не по сырому тексту; показывать в плашке, что часть связанных заметок обрезана.

**D-07. Отказ 402 (нужно подтверждение цены) расходует суточную квоту облачных запросов**
- `EnforceCloudRate()` вызывается до проверки `costConfirmed` и до каталога моделей (`AiService.cs:307` против `:314`). Любая ошибка после неё (модель не найдена, цена выше потолка, нет цен) тоже съедает один из 100 запросов.
- Доказательство: `QA11` (ожидалось callsToday 0, факт 1).
- Исправление: фиксировать вызов (`CloudCalls.Add`) перед отправкой, после всех проверок.

**D-08. Сканер секретов пропускает типичные русские формулировки**
- Не ловятся: `Пароль - Qwerty12345` (обычный дефис; в правиле только `:`, `=`, `=>`, `—`, `–`), `пароль от почты: …` (слова между ключом и разделителем), `password is …`, `логин admin / пароль …`.
- Доказательство: `QA10` (4 из 4 фраз не найдены). Существующие тесты проверяют только форматы с `:` `=` и длинным тире.
- Исправление: добавить дефис, «это/is/от …»: «слово-ключ + до 3 слов + разделитель или пробел + значение 6+ знаков с цифрой»; честнее показывать пользователю предпросмотр отправляемого.

**D-09. Диалоги «Файл изменён другой программой», «История версий», «Подтянуть текст из внешних файлов» не закрываются по Esc, фокус не переводится в диалог, нет ловушки фокуса**
- Esc-цепочка (`App.tsx:1318-1342`) не знает про `conflictDialog`, `history`, `refs`, `find`; `conflictDialog` не имеет `autoFocus`. При открытом диалоге Esc закрывает панель AI или инспектор за ним. `aria-modal="true"` заявлен, но фоновые элементы остаются доступны с клавиатуры. Глобальные Ctrl+W/Ctrl+N работают под открытым диалогом.
- Исправление: добавить состояния в Esc-цепочку, `autoFocus` на первое действие, `inert` на фон (в `AiAssistantPanel` ловушка уже есть: переиспользовать).

**D-10. Ссылка `[[…]]`, «Заметка за сегодня» и открытие из других мест на архивную заметку: вкладки нет**
- `openLinkByTitle` и `openDailyNote` ставят `noteView="folder"`, а `openTabs` отфильтровывается по `inSection` (`App.tsx:245-246`): активная заметка без вкладки и без строки в списке (в отличие от `chooseSearchResult`, который переключает на «Архив»). По коду, в окне не воспроизводилось.
- Исправление: как в `chooseSearchResult` (`setNoteView(doc.archived ? "archive" : "folder")`).

### Мелочь

- **D-11.** `SaveToSource` воссоздаёт удалённый или перенесённый файл и его папки по старому пути (`File.Exists` ложно, проверка пропущена, `Directory.CreateDirectory`). Доказательство: `QA07`.

Исправление: проверять длину до создания, читать байты и передавать хосту на декодирование.
- **D-13.** Масштаб: `Ctrl+Shift+=` (то есть Ctrl и «+» на большинстве раскладок) игнорируется — `matchShortcut` при Shift обрабатывает только Tab и Slash. Работают Ctrl+= и NumpadAdd. Исправление: разрешить Shift для `Equal`.
- **D-14.** Список результатов поиска: `role="option"` на кнопках в порядке Tab, поле без `aria-controls`/`aria-activedescendant`; выбранный вариант экранный диктор не объявит.
- **D-15.** Названия заметок берутся из первого заголовка; при правке заголовка входящие `[[ссылки]]` молча «ломаются», при дубликатах побеждает первая заметка. Клик по битой ссылке создаёт новую заметку.

- **D-17.** `ai-usage.json` можно обнулить или править (отрицательный расход отключает бюджет). Документировано как «подушка», не граница безопасности; для $5/мес. допустимо.
- **D-18.** Гонка: `Upsert` вызывает `WriteThrough` вне `_sync`; два параллельных вызова по одной заметке дают ложный «conflict» (собственная запись воспринята как чужая) и общий временный файл `path.PID.tmp`. Мост выполняет команды параллельно (`Task.Run`), но интерфейс (`HostSync.drain`) шлёт строго по очереди, поэтому в приложении это латентно. Доказательство: `QA09` (в событиях «saved, conflict, saved…»). Исправление: общий замок на запись источника по `id`.
- **D-19.** `DeletePermanently` не удаляет id из `Settings.WriteThroughIds` и из `_conflicts`/`_sourceBackup`; восстановление `.nhub` их тоже не сверяет. Доказательство: `QA08`.
- **D-20.** `reloadLibrary` (второй запуск программы, «Открыть файлы…», «Взять версию с диска») ждёт `bootstrap` и затем заменяет содержимое редактора; правки, набранные за это время, теряются из `contents` и редактора (в хост они не успевают). Окно — сотни мс на большой библиотеке. По коду (`App.tsx:1007-1032`), не воспроизведено.
- **D-21.** Дублирование заметки копирует в состояние UI `sourcePath`, `writeThrough`, `readOnly` исходной (`App.tsx:601`): копия выглядит привязанной к файлу, хотя на диске это новая локальная заметка.
