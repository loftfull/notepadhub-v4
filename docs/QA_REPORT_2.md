## 3. Новые находки (severity; подтверждение)
- N-01 Средняя: .nhub не очищает SourcePath/SourceType (NhubBackup.IsValidMeta проверяет только Id). После восстановления мост может: resolveSourceConflict("mine") записать заметку в любой существующий файл с разрешённым расширением (.bat/.cmd/.ps1/.js) без write-through и без реального конфликта; resolveReferencedFiles прочитать любой .json/.ini/.toml/.log локальный файл в заметку.
- N-02 Низкая: подтверждение облака (confirmCloud) не получает токен отмены; квота и бюджет списываются (CommitCloudCall/ReserveSpend) до SendWithRetry, поэтому отмена/таймаут 90 с во время диалога и сбой отправки сжигают квоту и бюджет. 90-секундный таймер идёт и во время диалога.
- N-03 Низкая: проверка CheckCloudRate и CommitCloudCall не атомарны (между ними await каталога моделей) — параллельные запросы превышают 10/мин.
- N-04 Низкая: _sourceBackup — обычный Dictionary, меняется из SaveToSource разных заметок без общего замка.
- N-05 Низкая: ImportFile не проверяет EditorLimitChars (262 144): файл 300 000 знаков открывается в редактор, любая правка отклоняется.
- N-06 Низкая: смешанные \r\n/\n приводятся к CRLF целиком.
- N-07 Низкая: SanitizeWriteThrough навсегда снимает write-through, если диск (USB) временно отсутствует.
- N-08 Низкая: переименование ссылок: заголовок с «|» или «[]» даёт ссылку [[B C]], не совпадающую с названием «B|C» — ссылка рвётся; ссылки в таблицах не переписываются; переписывание идёт и в файловые заметки (write-through) — правятся реальные файлы пользователя; если заметку со ссылкой открыть в течение 1,5 с, редактор не обновляется и переименование теряется при следующей правке.
- N-09 Низкая: IsAllowedSource проверяет reparse point только у самого файла, не у каталогов пути (junction).
- N-10 Низкая: глобальные Ctrl+W/Ctrl+N/Ctrl+K работают под открытым модальным диалогом; ловушка фокуса зависит от булева anyDialogOpen и берёт первый диалог в DOM при вложенных.

Исправления (рекомендации): N-01 при восстановлении .nhub сбрасывать SourcePath/SourceType (или показывать пути в ConfirmRestore), "mine"/"disk" разрешать только при IsWriteThrough и активном конфликте, resolveReferencedFiles подтверждать нативным диалогом хоста; N-02 передавать CancellationToken в confirmCloud, запускать таймер 90 с после подтверждения, резервировать после успешной отправки; N-03 делать check+commit под одним замком; N-04 ConcurrentDictionary; N-05 в ImportFile считать файл > EditorLimitChars ExternalOnly; N-06 сохранять исходный стиль строк построчно; N-07 не снимать write-through при недоступном диске; N-08 нормализовать заголовок так же, как ссылку, или не переименовывать при «|[]»; обновлять редактор активной заметки, обрабатывать table; N-09 проверять ReparsePoint у каждого каталога пути.

## 4. Что не проверено
- Окно программы: диалоги, Esc, фокус, drag-and-drop, «заметка за сегодня», гонка переименования ссылок при быстром переключении заметки (N-08) — только чтение кода, e2e их не покрывает.
- Закрытие окна во время нативного диалога подтверждения облака; диалог из не-UI потока (Dispatcher.InvokeAsync — по коду безопасно).
- TOCTOU подмены файла на symlink между проверкой и записью (нужны права для symlink); File.Replace на сетевых/залоченных файлах и FAT; сохранение UTF-16 без BOM (импорт такого файла отклоняется как двоичный).
- Конфликт Ctrl+K с «ссылкой» BlockNote; D-21; реальные Ollama/OpenRouter.
- Через мост страница путь не задаёт (openFiles — родной диалог; setWriteThrough/resolveSourceConflict — только id), но N-01 показывает, что id заметок из чужой .nhub дают запись/чтение по её путям; WriteThroughIds в .nhub не входит (settings не архивируются), поэтому подделать его нельзя.
- Совместимость 3.0.5: новых полей в NoteMeta нет (15 полей), e2e «byte-identical changed=0» и «3.0.5 format» пройдены; WriteThroughIds/OpenNoteIds только в settings-v4.json; ai-usage.json и ключ — в корне профиля вне data-v3.
