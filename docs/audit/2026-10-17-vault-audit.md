## 4. Что исправить в базе (по приоритету)

3. **Уроки → проверки.** Файлы `Lessons/*` описывают прошлые провалы, но ничего не запускают. Каждый урок должен превратиться в правило с условием срабатывания и проверкой.

## 6. Алгоритмы автоматического проектирования и автоподключения базы

### 6.1 Схема
```
Новая сессия или папка
  │ A. Найти корень проекта (по признакам, не по списку)
  │ B. Нет в реестре → автоматически занести в `governed.auto.txt`
  │    (владелец может вычеркнуть) + создать карточку проекта
  │ C. Определить профиль: стек, тип (настольное, сайт, мобильное),
  │    ИИ-функции, категория («заметки», «планировщик»…)
  │ D. Подать «пакет контекста» профиля: дайджесты (до 3000 слов)
  ▼
Запрос владельца
  │ E. Классификатор намерений: расположение/вид → UI_Quality_Loop;
  │    модель/ИИ → стандарт ИИ; «с нуля» → Preflight; push → проверка CI
  │ F. Каждое новое требование → в реестр требований (в тот же день)
  ▼
Работа
  │ G. Размер работы (Router) → H. Reuse-запись с предзаполнением
  │    из Reuse_Map по категории → I. SPEC/PLAN (spec_gate)
  │ J. Сборка с проверкой ловушек среды → K. Доказательства (снимки +
  │    измерения + тесты) → L. Независимый критик (отдельный агент)
  ▼
Конец хода
  │ M. Stop-хук: ворота + CI + «что установлено» + журнал прогресса
  │ N. Отчёт «собирается / работает / выглядит» только по доказательствам
  ▼
После провала или замечания
    O. Урок → правило (условие + проверка) → заявка владельцу на утверждение
```

### 6.2 Конкретные механизмы
1. **`detect_project_root.py`** (хук SessionStart): идёт вверх от текущей папки до первого признака проекта, исключает домашнюю папку и `_archive`. Вход: путь. Выход: корень, стек, список маркеров. Срок выполнения < 1 с.
2. **`governed.auto.txt`**: файл только для записи хуком; `governed_projects.txt` остаётся за владельцем. Ворота читают оба. Владелец видит новые строки и может вычеркнуть.
3. **`context_packs.yaml`**: профиль → список разделов базы с дайджестами. Пример: `wpf+webview2+react+ai` → Router, Reuse, UI_Quality_Loop (чек-лист), AI_Feature_Design_Standard (дайджест), ловушки среды, реестр требований. `build_context_pack.py` собирает не больше 3000 слов и подаёт через `SessionStart` и **`PostCompact`** (повторно после сжатия контекста).
4. **`intent_rules.yaml`** (хук `UserPromptSubmit`): слова и фразы → раздел базы. Пример: «расположение, шрифт, кнопка, дубль, выглядит, дизайн» → `UI_Quality_Loop` + реестр требований; «модель, ИИ, промпт, оценка» → стандарт ИИ + урок «smoke first»; «push, CI, релиз» → чек-лист выпуска. Хук добавляет 5–8 строк правила в контекст перед моим ответом.
5. **`lessons → rules`**: у каждого урока формат `{id, условие, проверка, как исправить}`. Примеры проверок, которые можно выполнить кодом:
   - UI-01: на экране нет двух элементов с одинаковой подписью (запрос в Playwright);
   - UI-02: в интерфейсе один шрифт и шкала размеров из `DESIGN.md` (`ui_measure.mjs`);
   - ENV-01: перед тестами окна дата `dist` не старее исходников;
   - CI-01: после push последний запуск CI зелёный (`gh run list`);
   - REQ-01: каждое «R-n» из реестра ссылается на тест;
   - HASH-01: хэш доказательств обновляет только инструмент после повторного прогона.
6. **`evidence_refresh.py`**: сам запускает сценарий, сам считает хэш по исходникам (без тестов и документов), сам пишет `journey.md`. Ручная правка хэша запрещена и ловится проверкой.
7. **`progress_ledger.py`** (Stop-хук): собирает из `git log`, реестра требований и результатов ворот файл `docs/PROGRESS.md`: что сделано, чем доказано, что не проверено, что ждёт решения владельца. Сводка по всем проектам идёт в `Dashboard.md`.
8. **Context Receipt**: в начале сессии хук создаёт файл «что подано в контекст» и проверяет, что я его подтвердил (пустая расписка = предупреждение).
9. **Предложения вместо правок**: инструменты и реестры базы правятся только через `Projects/change-plans/*` (формат уже есть) с решением владельца. Хук `guard.py` блокирует прямую запись в `_meta/tools`, если нет открытого решения.
10. **Метрики здоровья** (раз в неделю, `vault_lint.py`): доля сессий с подачей пакета контекста; число сработавших правил; число замечаний владельца на 100 ходов (цель: снижение); число заметок с просроченным `last_reviewed`; число `proposed` старше 14 дней.
